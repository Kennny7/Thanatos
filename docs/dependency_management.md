# Dependency Management

This document explains how Thanatos manages its Python and Flutter/Dart dependencies in a **reproducible, version-locked** way to prevent unexpected breakage from upstream library updates.

---

## The Problem We Solved

Previously, both `requirements.txt` (Python) and `pubspec.yaml` (Flutter) used open-ended version ranges (`>=X.Y.Z` and `^X.Y.Z` respectively). This means:

- `pip install -r requirements.txt` could silently pull in a **newer, breaking version** of a library the next time someone installs the project.
- Two developers on different machines — or a CI server — could end up with different library versions, making bugs hard to reproduce.

---

## Python: `uv` + Lock File

### Tool: [`uv`](https://docs.astral.sh/uv/)

`uv` is a fast, Rust-based Python package and project manager by Astral (the makers of `ruff`). It replaces `pip` + `venv` + `pip-tools` in a single tool.

### How versions are pinned

`pyproject.toml` uses **compatible-release (`~=`) specifiers** instead of open-ended `>=`:

| Specifier | Meaning | Example |
|---|---|---|
| `>=2.32.0` ❌ | Any version ≥ 2.32.0 (unbounded) | Could install 3.x |
| `~=2.32` ✅ | `>=2.32, ==2.*` — minor is locked | Allows 2.33, 2.34 but not 3.0 |
| `~=2.32.0` ✅ | `>=2.32.0, ==2.32.*` — patch only | Allows 2.32.1 but not 2.33 |

This still allows security patches but prevents surprise major/minor API breaks.

### `uv.lock` — the source of truth

`uv lock` resolves the full dependency graph (including transitive deps) and writes every package's **exact version, hash, and wheel URL** to `uv.lock`. This file is:

- **Committed to git** — everyone gets identical installs.
- **Cross-platform** — `uv` handles platform markers automatically.
- **Automatically updated** — run `uv lock` whenever you change `pyproject.toml`.

### Common commands

```bash
# Install exact versions from the lock file (primary workflow)
uv sync

# Also install dev/test dependencies
uv sync --extra dev

# Add a new package (updates pyproject.toml and uv.lock)
uv add <package>

# Add a dev-only package
uv add --optional dev <package>

# Upgrade a specific package and update the lock file
uv lock --upgrade-package <package>

# Upgrade all packages within their ~= constraints and update lock
uv lock --upgrade

# Regenerate the lock file after manually editing pyproject.toml
uv lock

# Run a command inside the uv-managed virtual environment
uv run python -m pytest
uv run uvicorn apps.api_server.main:app --reload
```

> [!NOTE]
> `uv sync` automatically creates and manages a `.venv/` virtual environment in the project root. You do **not** need to create one manually.

> [!TIP]
> `uv run <command>` activates the environment automatically, so you don't need to `source .venv/bin/activate` before every command.

### Fallback: pip (if `uv` is unavailable)

`requirements.txt` is kept for legacy compatibility. It now uses `~=` pins instead of `>=`, so it's safer than before — but it still does **not** guarantee byte-for-byte reproducibility across installs.

```bash
python -m venv venv
# Windows:
venv\Scripts\activate
# macOS / Linux:
source venv/bin/activate

pip install -r requirements.txt
```

## Flutter/Dart: `pubspec.lock`

### Version strategy in `pubspec.yaml`

Dart's `^X.Y.Z` (caret) specifier is equivalent to `>=X.Y.Z <(X+1).0.0` — it allows minor and patch updates but not major-version bumps. This is safe and is the Dart community standard.

### `pubspec.lock` — committed to git

The `pubspec.lock` file is generated by `flutter pub get` and records the **exact resolved version** of every Dart package. It was previously excluded from version control (`.gitignore`); we now **commit it**.

```bash
# Regenerate / refresh the lock file
cd apps/client_flutter
flutter pub get
```

When collaborators pull the repo and run `flutter pub get`, Dart will respect the lock file and install the same exact versions.

> [!IMPORTANT]
> `pubspec.lock` **must be committed** to git. Never add it back to `.gitignore`.

### Upgrading Flutter dependencies

```bash
cd apps/client_flutter

# Show which packages have newer versions available
flutter pub outdated

# Upgrade all packages within pubspec.yaml constraints (updates pubspec.lock)
flutter pub upgrade

# Upgrade a single package to latest compatible version
flutter pub upgrade <package_name>
```

## Summary: Files & Their Roles

| File | Language | Purpose | Committed? |
|---|---|---|---|
| `pyproject.toml` | Python | Declares dependencies with `~=` version constraints | ✅ Yes |
| `uv.lock` | Python | Exact resolved versions for all deps (generated by `uv lock`) | ✅ Yes |
| `requirements.txt` | Python | Legacy pip fallback (also uses `~=` pins) | ✅ Yes |
| `apps/client_flutter/pubspec.yaml` | Dart | Declares Flutter deps with `^` constraints | ✅ Yes |
| `apps/client_flutter/pubspec.lock` | Dart | Exact resolved versions for all Dart deps | ✅ Yes (was gitignored — now tracked) |

---

## CI/CD Recommendation

For GitHub Actions or any CI pipeline, always install with the lock file:

```yaml
# Python
- name: Install uv
  uses: astral-sh/setup-uv@v4
- name: Install dependencies
  run: uv sync --extra dev

# Flutter
- name: Install Flutter deps
  run: flutter pub get   # respects pubspec.lock automatically
  working-directory: apps/client_flutter
```
